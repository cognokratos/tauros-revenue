# Development

## Prerequisites

- Erlang/OTP and Elixir at the versions in `.tool-versions` (`asdf install` or `mise install`)
- PostgreSQL 15+ at `localhost:5432` with user and password `postgres`. The
  quickest way is Docker:

  ```bash
  docker run -d --name tauros-postgres -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:17-alpine
  ```

## Everyday commands

| Command | What it does |
| --- | --- |
| `mix setup` | deps, database (`ash.setup`), assets, demo seeds |
| `mix phx.server` | run at <http://localhost:4000> |
| `mix test` | set up the test database and run the suite |
| `mix precommit` | compile with warnings as errors, unlock unused deps, format, credo, sobelow, test |
| `mix ash.codegen <name>` | generate migrations after changing resources |
| `mix ash.reset` | drop and recreate the database |
| `mix ash_json_api.routes` | print the JSON:API routes |

The seeds print a demo login (`demo@tauros.local` / `tauros-demo-password`) and a
fresh agent API key.

## Working on the domain

1. **Use a generator if one exists.** Run `mix help | grep -E "ash|igniter"`.
   Prefer `mix ash.gen.resource`, `ash.gen.change`, `ash.gen.validation`,
   `ash.gen.preparation`, `ash.gen.enum`, `ash.extend`,
   `ash_authentication.add_strategy` / `add_add_on`, `ash_phoenix.gen.live` and
   `mix igniter.install <package>` over writing files by hand.
2. **Put the rule in the resource.** Choose an attribute constraint, `accept`
   list, validation, change, policy or calculation. Don't put rules in
   LiveViews or plugs.
3. **Call actions through the domain code interface** with an explicit `actor:`.
   Use `authorize?: false` only in fixtures, seeds and changes that run inside an
   already-authorized action.
4. **Generate the migration**: `mix ash.codegen describe_the_change`. Review it,
   commit it with its snapshots, and don't edit it by hand. CI runs
   `mix ash.codegen --check`.
5. **Test the action first** in `test/tauros/**`, including the actors who must
   be refused. Then test the interface.

Fixtures in `test/support/fixtures.ex` go through the real actions, so they
obey the same policies the app does.

## Generators

The complete generator history of the rewrite:

```bash
mix igniter.new tauros --with phx.new --with-args="--binary-id" \
  --install ash,ash_postgres,ash_phoenix,ash_json_api,ash_authentication,ash_authentication_phoenix \
  --auth-strategy magic_link
mix ash_authentication.add_strategy password --hash-provider argon2

mix ash.gen.resource Tauros.Accounts.Agent -u id -a name:string:required:public \
  -r belongs_to:user:Tauros.Accounts.User:required --timestamps \
  -e postgres,Ash.Policy.Authorizer,AshJsonApi.Resource --default-actions read,destroy
mix ash_authentication.add_strategy api_key --user Tauros.Accounts.Agent --api-key Tauros.Accounts.ApiKey
mix ash.gen.change Tauros.Accounts.Agent.Changes.IssueApiKey
mix ash.extend Tauros.Accounts.User json_api

mix ash.gen.resource Tauros.Revenue.Customer -u id \
  -a name:string:required:public,email:string:required:public \
  -r belongs_to:agent:Tauros.Accounts.Agent:required:public --timestamps \
  -e postgres,Ash.Policy.Authorizer,json_api --default-actions read,destroy
mix ash.gen.enum Tauros.Revenue.Currency BTC,ETH,USDT,USDC,DAI,TUSD,BUSD,FDUSD,GUSD,PAX,USDP,LUSD,FRAX,SUSD,USD,EUR,CHF,GBP,JPY,CAD,AUD,NZD,SEK,NOK,DKK,SGD
mix ash.gen.resource Tauros.Revenue.WalletAccount -u id \
  -a wallet_name:string:required:public,public_address:string:required:public,currency:Tauros.Revenue.Currency:required:public \
  -r belongs_to:agent:Tauros.Accounts.Agent:required:public --timestamps \
  -e postgres,Ash.Policy.Authorizer,json_api --default-actions read

mix ash_phoenix.gen.live --domain Tauros.Accounts --resource Tauros.Accounts.Agent --resource-plural agents
mix ash_phoenix.gen.live --domain Tauros.Revenue --resource Tauros.Revenue.Customer --resource-plural customers
mix ash_phoenix.gen.live --domain Tauros.Revenue --resource Tauros.Revenue.WalletAccount \
  --resource-plural wallet_accounts --resource-plural-for-routes wallet-accounts
#   answers: multi-tenancy "n"; actor "y", named current_user

mix ash.codegen initial_schema
mix igniter.install credo sobelow mix_audit --only dev,test
mix credo gen.config
```

## Quality checks

CI (`.github/workflows/ci.yml`) runs these against PostgreSQL 17:

| Check | Tool |
| --- | --- |
| formatting | `mix format --check-formatted` (Spark and HEEx formatter plugins) |
| compiler, including Elixir's type checker | `mix compile --warnings-as-errors` |
| static analysis | `mix credo` (default config; `AliasUsage` disabled because generated code doesn't follow it) |
| Phoenix security | `mix sobelow --exit` |
| vulnerable or retired deps | `mix deps.audit`, `mix hex.audit` |
| lockfile hygiene | `mix deps.unlock --check-unused` |
| migrations in sync with resources | `mix ash.codegen --check` |
| behaviour | `mix test` |

**Dialyzer is not used.** Since Elixir 1.18, the compiler's set-theoretic
type checker catches the class of bugs that justified Dialyzer for an
application like this. Spark DSL modules produce long, noisy PLT builds, and
the policy and action tests cover the invariants that matter. Reconsider if
the project grows a library-style public API.

## Configuration for production

`config/runtime.exs` reads `DATABASE_URL`, `SECRET_KEY_BASE`,
`TOKEN_SIGNING_SECRET`, `PHX_HOST`, `PORT` and optionally `MAIL_FROM`. Configure
a real Swoosh adapter before enabling magic links or password resets in
production.
